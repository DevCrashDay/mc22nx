# Switch 30 fps (overclock + faster raster) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Midnight Club II's Switch NRO reaches ≤ 33.3 ms/frame docked in every harness section on the 2017 Switch, by
setting kit/stock overclocks from inside the NRO and cutting the raster shader's wasted GPU work, with pixels unchanged.

**Architecture:** A small Switch-only clock module (pure decision logic in a header testable on PC, libnx `clkrst`/`pcv`
calls in one `.cpp`) applied from `host/main.cpp`. Raster work reduction is measured on the CPU side in `gpu.cpp` (the
per-tile primitive lists are built there), then implemented as a build-time GLSL transform in
`scripts/glsl_raster_lean.py` (applied to GL and deko3d), so the PC 75-image check guards it.

**Tech Stack:** C++20, libnx (devkitA64), deko3d + uam, CMake, Python 3 scripts; llvm-mingw for the PC GL build.

**Spec:** `docs/superpowers/specs/2026-11-15-switch-30fps-design.md`

All paths below are relative to `MC2Recomp/ps2-native-recomp/` unless they start with `tools/`, `baseline/` or `docs/`
(project root `%USERPROFILE%\Downloads\mc2`). Build/run commands: `HANDOFF.md` "How to build and test".

## Global Constraints

- Clock targets: kit CPU **2091 MHz**, kit GPU **1228.8 MHz** (docked only); stock fallback CPU **1785 MHz**, GPU **921.6 MHz**; RAM (EMC) never set, only logged.
- GPU raised only when `appletGetOperationMode() == AppletOperationMode_Console`; handheld: CPU raised, GPU untouched.
- `PS2_CLOCKS=0` leaves clocks alone; `PS2_CLOCKS=<cpu MHz>,<gpu MHz>` requests exactly those (same read-back fallback).
- Clocks re-applied about every 1 s while running; previous rates restored on normal exit and in `__libnx_exception_handler`.
- Pixels: PC GL build, all 75 harness images 0 diff vs `baseline/pc-gl` (`tools/compare.py --tol 0 --max-pct 0`).
- Toolkit base stays v0.0.4 + MC2 patch; shader changes go through `scripts/glsl_raster_lean.py`, never hand edits of `glsl/*`.
- Switch code behind `__SWITCH__`; PC and OpenGL Switch builds keep building.
- Hardware runs cost the user a netloader press each: batch measurements; nothing is committed unless the user asks (commit steps below run only with the user's go-ahead).

## Review Focus

- Console undocked mid-game: GPU must drop back to the system's handheld value (no kit/docked GPU rate in handheld) — Task 2 step "dock/undock" check.
- Kit absent: request of 2091 reads back lower → NRO must use 1785, not stay at whatever partial value — Task 1 tests `next_request`.
- Crash while overclocked: crash handler restores clocks before `svcExitProcess` — Task 2 hardware check with `PS2_CRASH_TEST`-style forced fault if one exists, else code review of the handler order.
- Ryujinx (clock services stubbed / rates read back 0): no crash, log says clocks unavailable — Task 2 Ryujinx run.
- Malformed `PS2_CLOCKS` (`abc`, `2091`, `2091,`, negative): treated as "no override" with a log line, never a zero clock — Task 1 tests.

**Files:**
- Create: `host/switch_clocks_logic.hpp`
- Create: `tests/switch_clocks_logic_test.cpp`

**Interfaces:**
- Produces:
  - `struct ClockRequest { bool leave_alone; std::uint32_t cpu_hz; std::uint32_t gpu_hz; bool custom; };`
  - `ClockRequest parse_clock_env(const char *value)` — `nullptr`/empty → kit targets; `"0"` → `leave_alone`; `"<cpu>,<gpu>"` MHz → `custom`; malformed → kit targets.
  - `std::uint32_t next_request(std::uint32_t requested_hz, std::uint32_t readback_hz, std::uint32_t stock_max_hz)` — returns 0 when `readback_hz >= requested_hz - 1'000'000` (took; tolerance for table rounding), else `stock_max_hz` if `requested_hz > stock_max_hz`, else 0 (give up, keep readback).
  - constants `kKitCpuHz = 2'091'000'000`, `kKitGpuHz = 1'228'800'000`, `kStockCpuHz = 1'785'000'000`, `kStockGpuHz = 921'600'000`.

### Task 3: Measure the raster waste (CPU-side counters, PC run)

**Files:**
- Modify: `runtime/src/gs/gpu/gpu.cpp` (`add_spans` ~line 895 and `note_raster` ~line 1093; a `RasterWaste` accumulator printed every 300 presented frames when `PS2_RASTER_STATS=1`)
- Modify: `HANDOFF.md` (results)

**Interfaces:**
- Produces: log line `[raster-stats] 300 frames: entries <n>, thread-visits <n> (tile 16), warp-runs <n> (tile 16) / <n> (tile 8), bbox-pixels <n>, lane-use <pct>% (16) / <pct>% (8)`.
  Definitions: entry = one (tile, primitive) pair; thread-visits = entries × tile²; a warp = 32 threads = 16×2 pixels at tile 16, 8×4 at tile 8; warp-runs = warps whose pixel block intersects the primitive's bbox; bbox-pixels = Σ clipped bbox pixel counts; lane-use = bbox-pixels / (warp-runs × 32).

- [ ] **Step 1: Implement the counters** (compute both tile geometries from each primitive's `lo`/`hi` bbox in `add_spans`, independent of the real `g_tile`; zero cost when the env var is unset).

- [ ] **Step 2: PC run** of the harness (`tools/harness.sh` with `PS2_RASTER_STATS=1` exported, PC GL build). Expected: `[raster-stats]` lines; pixels still 0 diff (counters only).

- [ ] **Step 3: Record in `HANDOFF.md`** the race-section numbers (frames 3000–3700) and the decision for Task 4: tile 8 if its lane-use is clearly higher (≥ 1.5× tile 16's); otherwise the group-level early-out (Task 4 alternative).
